# 선물 기능시험: 레버리지와 보호 손절

이 기능은 Live Trader의 5~7시간 소액 기능시험 화면에서 Binance USDⓈ-M 선물을 실행할 때 적용한다. 사용자가 전략과 정책을 선택하고 준비 검사를 거쳐 직접 시작한다. 앱을 열거나 준비 검사만 해서는 주문하지 않는다. 일반 SMALL/FULL LIVE 승격 기준이나 수익성 검증 통과를 대신하지 않는다.

## 사용 순서

1. 거래소에서 해당 심볼의 레버리지와 격리 설정을 직접 정한다.
2. 기능시험 화면에서 같은 기대 레버리지와 보호 손절 비율을 입력한다. 손절 비율은 진입 주문 가격에서 떨어진 가격 거리이며, 계좌 손실률과 다르다.
3. 전략을 선택하고 새 준비 검사를 수행한다. 준비 결과는 검사 완료부터 3분간 유효하다. 실제 거래소 설정과 값이 다르면 시작을 막는다. 정책을 변경하면 이전 준비 결과와 사용자 확인을 폐기한다.
4. 결과와 거래 허용 제어를 확인한 뒤 사용자가 실제 시작 버튼을 누른다. 전략 신호가 있어야 주문하며 주문 발생을 위해 신호를 만들지 않는다.

기존 v1 준비 결과는 재사용하지 않는다. 앱 재시작으로 기존 세션을 복원하거나 새로운 주문을 자동 재개하지 않는다.

`신규 진입 차단`은 새 포지션이나 노출을 늘리는 주문을 막는 운영 제어다. `실거래 운용 → 한도·안전장치 → 운영 차단 설정`에서 상태를 확인하고 정상 확인 절차로 해제할 수 있다. 계좌·포지션 대조 실패 등 안전 점검이 다시 차단할 수 있으므로 원인을 확인한 뒤 새 준비 검사를 수행한다. 준비 유효시간과 이 차단은 별개이며, 3분 안에 시작하더라도 서버는 현재 운영 제어·계좌·원본·시각 조건을 다시 검사한다.

## 시작 설정과 중복 확인

- **모의 실행**: 앱 시작 시 켜지는 주문 전송 방지 설정이다. 시험 화면의 `모의 실행 해제`는 기존 운영 설정과 같은 확인 절차를 사용한다. 앱 전체 설정을 바꾸며 시험을 자동 시작하지 않는다. 변경 후 전략 선택은 유지하지만 이전 준비 결과와 동의는 폐기하고 새 무주문 준비 검사가 필요하다.
- **운영자 확인**: 이 단기 시험은 마지막 시작 화면의 체크박스와 정확한 확인 문구, 준비 ID·범위·3분 유효시간으로 동의를 받는다. 별도 전역 `운용자 확인`을 먼저 켜는 중복 조건은 제거했다. 일반 SMALL/FULL LIVE 조건은 그대로다. 운영 중 전역 운용자 확인을 명시적으로 해제하면 단기 시험에도 중지 요청이 적용된다.
- **신규 진입 차단**: 앱 시작 대기, 수동 차단, 계좌·원장 불일치, 조회 오류 및 위험 감시 이상에 사용하는 운영 제어다. 오류가 남아 있으면 해제 후 다시 차단될 수 있으므로 무시하지 않는다. 새 매수·노출 증가를 막으며 이미 접수된 주문을 취소하는 스위치는 아니다. 확인된 위험 감소 주문과 보호는 각자의 별도 조건을 따른다.

## 자금과 레버리지

- 10만원 한도는 실제 사용할 자본이다. Binance 현물·선물은 기존 Binance 합산 한도를 공유한다.
- 5배면 같은 증거금으로 명목 노출이 커지지만, 잔고를 5배로 기록하지 않는다. 수수료와 펀딩 예비금을 주문 가능액에서 제외하고 실제 가용 자금보다 크게 주문하지 않는다.
- 화면의 포지션 투입 증거금과 명목 노출은 서로 다른 값이다. 거래소 최소 주문·수량 격자·최대 수량·유지증거금 구간도 적용된다.
- 손실 중단은 실제 계좌 평가 감소와 최신 환율을 주기적으로 확인하는 기준이다. 급변·슬리피지·조회 지연 때문에 설정한 손실액을 초과할 수 있다.
- 거래소 실제 레버리지·증거금 모드가 세션 중 바뀌면 신규 진입을 막는다. 확인된 자기 포지션의 위험 감소 주문은 설정 불일치만으로 막지 않는다.

## 보호 주문과 청산 감지

- 진입 전에 MARK_PRICE 기반 STOP_MARKET closePosition 주문을 제출하고 정확한 원 client ID로 거래소의 NEW 상태를 확인한다. 진입과 보호 주문은 원자적 거래가 아니므로 보호 주문 확인 실패 시 진입하지 않는다.
- 유지증거금 구간과 비용을 고려한 보수적 사전 검사를 한다. 포지션 생성 후에는 거래소 실제 liquidationPrice와 markPrice를 추가 대조한다.
- 여러 전략이 같은 심볼을 보유하면 공유 포지션 보호 주문을 관리한다. 추가 진입 시 기존 손절을 느슨하게 하지 않는다. 교체할 때 새 보호 주문 확인 후 이전 주문을 정리한다.
- 거래소 보호 손절의 실제 자식 주문·체결·수수료를 원장에 반영한다. 강제청산과 ADL은 공식 강제종료 기록과 실제 주문·체결을 연결한 경우에만 분류한다. 단순 잔고 변화나 수동 주문은 청산으로 추정하지 않는다.
- 응답이 유실되면 원래 client ID를 조회한다. 같은 주문을 재전송하거나 다른 ID로 바꾸지 않는다. 이후 읽기로 확인되어도 최초 실패를 보존하고 자동 재진입하지 않는다.
- 중단 시 자기 세션의 미체결과 포지션을 확인하고, 확인된 포지션의 시장가 위험 감소 주문을 한 번만 시도한다. 포지션이 실제로 비고 일반 주문도 종료된 뒤 보호 주문을 정리한다.
- 종료 판정에는 포지션·일반 주문 부재뿐 아니라 보호 주문과 실제 자식 주문의 확인된 종료가 필요하다. UNKNOWN은 완료로 바꾸지 않는다.

거래소 손절 주문은 청산 방지나 지정 가격 체결을 보장하지 않는다. 네트워크 단절·거래소 거부·가격 급변·전역 비상 잠금에서는 앱의 추가 주문이 차단되거나 정리가 완료되지 않을 수 있다. 전역 비상 잠금을 우회하지 않으며 이미 접수된 거래소 보호 주문은 임의로 제거하지 않는다.

## 검증 범위

자동 테스트는 가짜 계좌·주문·체결 자료로 수행한다. 실제 주문 시작, 주문/취소, 계좌 레버리지·증거금 모드 변경, 입출금은 빌드 검증에 포함하지 않는다. 실제 접수·체결 검증은 사용자가 시작한 세션에서만 확인할 수 있다.
