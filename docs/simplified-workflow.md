# Live Trader: 간결한 검증·운용 흐름

## 최종 목적

Paper Trader에서 모의 검증을 마친 전략이 실제 주문·체결·잔고 환경에서도 안전하게 동작하는지 제한된 범위로 확인하고, 근거와 별도 승인을 갖춘 뒤 실전 운용한다. 화면의 검증 단계가 높다고 주문 권한이 자동으로 열리는 것은 아니다.

공통 전략 흐름은 **백테스트 → 모의 검증 → 제한 실거래 → 실전 운용**이다. Stock Data Scraper의 데이터 준비는 이 흐름의 입력이다. 전략 작성은 백테스트 안의 준비 작업이며, 신호 관찰(SHADOW)과 가상체결(PAPER)은 하나의 모의 검증 안에 남아 있는 별도 검사다.

## 탭별 역할과 확인 순서

| 탭 | 하는 일 | 확인할 정상 동작 |
|---|---|---|
| 시작 점검 | 연결·미체결·대조·시세·배포 차단 사유를 확인 | 미실행·조회 실패를 통과로 표시하지 않으며, 필요한 조치로 이동 가능 |
| 운용 전략 | Paper의 모의 검증 근거와 현재 전략·배포를 확인 | 검증 진행과 실행 허용 범위가 구분됨. 전략 전환은 명시적으로 선택할 때만 일어남 |
| 실거래 운용 → 한도·안전장치 | 자본·손실·신규 진입 차단과 주문 안전장치 확인 | 현재 사용량을 확인하고, 모르는 값은 0이 아닌 미확인으로 표시 |
| 실거래 운용 → 실행·중지 | 승인된 제한 실거래 또는 실전 운용의 시작·중지 | 모드를 선택하는 것만으로 실행하지 않음. 현재 배포·계좌·승인 범위로만 실행 |
| 계좌·잔고 | 브로커 조회·실시간 체결·내부 원장을 비교 | 조회 이력 없이 잔고가 일치한다고 하지 않음. 실패나 미체결은 정리 전까지 유지 |
| 주문·체결 | 주문 생성부터 접수·체결·취소·대조까지 추적 | 불확실한 주문을 바로 재전송하지 않고 동일 주문 ID로 대조 |
| 실행 기록 | 운영 이력과 상세 로그 검색 | 운영 변경 기록과 엔진 상세 로그를 내부 탭으로 구분 |
| 연결·설정 | 증권사·거래소 연결과 화면·알림 설정 | 설정 변경과 실제 주문 승인을 구분 |
| 주문 연결 시험 | 최초 연결·주문 경로 변경 시 증권사/거래소의 주문·중지·복구 확인 | 전략 승급과 분리됨. 실자금이 사용될 수 있으며 기존의 별도 승인·중지·복구 요건 유지 |

주문 연결 시험은 위 전략 흐름에 추가되는 필수 다섯 번째 단계가 아니다. Paper Trader의 KIS 모의계좌 시험과 Live Trader의 실주문 시험도 서로 다른 환경이다. 어느 쪽이든 연결 시험 결과만으로 전략 수익성 검증이나 실전 운용 승인을 대신할 수 없다.

## 기존 기록과의 호환

- `draft`, `backtested`, `before-shadow`, `shadowed`, `papered`, `before-live-small`, `live`와 승인 코드는 그대로 보존한다. 저장된 아티팩트·해시·감사 기록을 일괄 변경하지 않는다.
- `before-live-small`은 **제한 실거래 대기**이지 실거래 검증 완료가 아니다.
- 예전 `risk` 화면 링크는 **실거래 운용 → 한도·안전장치**, `audit`는 **실행 기록 → 상세 로그**로 열린다. 저장한 마지막 화면과 진단 링크는 유지한다.
- 이전 세션의 `DRAINING`, 미체결, 대조 실패, 만료 승인, 계좌·배포 불일치는 메뉴를 합쳐도 해제되지 않는다.

## 수동 검증 시 주의

먼저 실주문 없는 화면·조회 검증을 진행한다. `미실행`, `미확인`, `대조 필요`가 남아 있으면 시작 버튼을 누르지 말고 차단 원인을 해결한다. 제한 실거래와 주문 연결 시험을 실제 실행할 때는 해당 경로의 별도 네이티브 승인, 계좌 범위, 주문·시간·손실 한도 및 안전 종료 절차를 따른다.
