# 국내·해외 공통 원화 예약

같은 KIS 계좌의 로컬 원화 예산을 국내·해외 사용처가 공유한다. 예를 들어 승인한 공통 예산이 100만 원이면 국내에 60만 원을 예약한 뒤 해외에는 최대 40만 원을 예약할 수 있다. 해외 통화로 표시된 주문가능액을 원화에 더하거나, 임의 환율로 달러 원금을 만들지 않는다.

## 구현된 동작

- 계좌 `accountFingerprint` 하나당 불변 원화 예산을 한 개만 저장한다. 통화·포트폴리오·API 설정을 바꿔 별도 예산으로 분리하지 않는다.
- 같은 SQLite `BEGIN IMMEDIATE` 트랜잭션에서 예약, 원금 기록, 현재 설정·취소 여부를 검사한다. 중간에 실패하면 예약과 원금이 함께 취소된다.
- 같은 예약 ID와 같은 내용은 재시작 후에도 한 번만 반영한다. 같은 ID의 금액·계좌·Source·정책이 달라지면 거부한다.
- 원화 원금보다 작은 금액을 예약할 수 없다. 소수 원금은 원화 예약에서 올림으로 덮는다.
- 외화 사용처의 **원화 예산**은 예약할 수 있다. 실제 외화 원금 초기화는 별도 자금·환전 검증 생산자가 생길 때까지 차단한다.
- 중지, 시간 경과, 주문의 `filled`·`expired` 표시만으로 예약을 풀지 않는다. 확정 해제 근거의 검증 생산자가 없으므로 해제 호출은 현재 항상 차단한다.
- 저장된 정책·영수증의 봉인, 순번·누적 합계·직전 해시, 중복 입력과 DB 동시 변경을 확인한다. 손상·충돌·DB 접근 실패 시 예약을 추가하지 않는다.

## 한 공통 파일을 쓰는 이유

통합증거금 모드는 소스 실행본과 패키지 실행본 모두 `%LOCALAPPDATA%/live_trader/logs/kis_owned_capital_v2.sqlite3`를 사용한다. 실행 폴더가 바뀌어 과거 예약을 모르는 두 번째 예산을 만드는 일을 막는다. 상대경로 `LOCALAPPDATA`는 거부한다.

현재 실행 폴더에 별도 기존 원장이 있으면 자동으로 옮기거나 지우지 않고 이전 검토를 요구한다. 공통 파일 안의 기존 원금에도 대응하는 예약이 없으면 자동 전환하지 않는다. 이 검사는 임의의 모든 과거 복사본이나 다른 PC·다른 사용자의 원장, 증권사 수동 주문까지 발견했다는 보장이 아니다. 실제 계좌 전체 자금 대조는 별도다.

명시적 `FOREIGN_CASH`는 기존 경로를 유지한다. 다만 같은 DB에 공통 예산이 이미 존재하면 기존 통화별 초기화로 공통 예약을 우회할 수 없다. 테스트는 명시적으로 주입한 임시 저장소만 사용한다.

## 수동 시작과 검증 경계

기존 계좌 심사의 `kisSharedKrwReservationPlan`에는 계좌 예산 정책과 해당 포트폴리오의 원화 예약액을 넣는다. 이 입력은 심사 문맥에 포함되고, 확인 화면에도 공통 상한과 예약액을 표시한다. 완성된 배포 scope가 생긴 뒤 결정론적으로 예약 요청을 만들므로 심사 해시와 scope 해시가 서로를 요구하는 순환이 생기지 않는다.

원금 초기화 관측에는 결제 방식과 정확한 예약 요청을 함께 봉인한다. 확정 직전과 같은 DB 트랜잭션 안에서 재검사하며, 운용 중 `POSITION` 조회와 일반 문맥도 현재 계획이 바뀌면 폐기한다. 운영 정책 해시에 예약 입력을 포함해 기존 준비·갱신 문맥이 재사용되지 않게 한다.

예약 기능은 **로컬 위험 예산**을 관리한다. 증권사 현금을 잠그는 기능이나 계좌 전체 현금·실제 수수료·환전·정산 완료 증명은 아니다. 이 기능의 성공으로 실주문 권한을 발급하지 않는다. 기본 통합증거금 모드는 KRX와 미국 모두 최종 티켓 검사에서 금융 검증 미완료로 차단하며, 위조한 예약 표시를 첨부해도 해제되지 않는다.

## 정보가 도착하면 이어갈 단계

사용자가 알려줄 OpenAPI 적용 매수·매도 요율, 최소수수료, 우대 종료일과 자동환전 우대를 비용 계약에 반영한다. 이후 실제 계좌 전체 미체결·외부 자금 변동, 공통 예산을 뒷받침하는 현금, 환전·최종 정산을 별도로 검증한다. 검증된 외화 원금과 확정 해제 생산자는 이 예약 저장소에 연결한다. 검증용 신규 매매·입금·환전은 필요 없다.

이번 구현 작업에서는 실제 계좌의 예산·원금·예약을 생성하지 않는다. 합성 테스트의 임시 SQLite 파일만 사용하며 중지된 예약 작업도 재개하지 않는다.
