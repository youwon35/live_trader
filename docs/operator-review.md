# 운영 검토 도구 (2026-09-10)

거래 권한을 바꾸지 않는 조회·비교와 개인 메모 기능입니다. 새로운 탭 대신 기존 위치에 요약과 펼침을 추가했습니다.

1. 모든 화면 상단 **조회 중인 배포 / 실제 실행**: 실제 실행 중인 프로필의 세션 ID와 그 세션이 고정한 배포 검증값으로 전략·버전·거래 경로·계좌 식별값을 읽습니다. 조회 선택이 달라도 실행 정보는 바뀌지 않습니다. 계좌 식별값은 계좌번호 대신 고정된 해시 앞부분입니다.
2. **시작 점검 → 직전 시작 점검과 비교**: 새 문제·심화와 해결을 먼저 요약합니다. 직접 실행한 시작 점검만 배포별로 저장하고, 폴링 결과는 이력으로 저장하지 않습니다. 검사가 사라졌다고 해결로 처리하지 않습니다. 첫 점검은 비교 기준을 만드는 단계입니다.
3. **실거래 운용 → 실행·중지 → 새 주문이 없는 이유**: 중지/조건 대기, 현재 권한 제한, 위험 차단, 이 배포의 검증된 최근 무신호를 구분합니다. 다른 배포의 신호나 과거 위험 차단을 현재의 확정 원인으로 대신 사용하지 않습니다.
4. 같은 위치의 **중지 방법별 영향 비교**: 신규 진입 차단, 감시 중지, 전체 긴급 정지의 새 주문·미체결·보유 자산 영향을 비교합니다. 취소 요청 성공과 취소 완료는 다르며 자동 청산을 약속하지 않습니다. 기능 검사 세션은 기존 전용 안전 종료를 사용합니다.
5. **계좌·잔고 → 종목·체결·수수료 대조 근거**: 앱 수량, 거래소 수량, 차이와 최근 체결 원장을 함께 보여줍니다. 선물 방향을 합치지 않고 누락 수량을 0으로 표시하지 않습니다. 확인되지 않은 수수료 통화나 개별/누계 기준은 합산하지 않습니다. 최근 원장만으로 수수료가 잔고 차이의 원인이라고 단정하지 않습니다.
6. **실거래 운용 → 한도·안전장치 → 리스크 정책·재시도·선물 계산 → 리스크 한도 설정**: 전략별 자본 한도를 입력하면 현재 선택 종목의 보유 사용량과 보유 기준 잔여를 바로 계산합니다. 기존과 같이 입력칸을 벗어날 때 저장 요청됩니다. 원화 현물의 확인된 수량×현재 시세만 사용합니다. 외화·선물·조회 실패는 원화로 추정하지 않습니다. 미체결 주문이 있으면 추가 주문 가능액은 미확인으로 안내하며, 계산값은 주문 허가가 아닙니다.
7. **운용 전략 → 기존 배포와 달라진 설정**: 실행 중 고정 버전이 있으면 그 버전, 없으면 직전 저장 버전과 현재 조회 배포 설정을 비교합니다. 정확한 포트폴리오 저장본 검증값이 일치한 목표 비중만 사용합니다. 과거 위험 설정의 세부값이 없으면 검증값 변경 여부만 알 수 있다고 표시합니다. 앞으로 직접 실행하는 점검은 해당 검증값과 위험 설정을 함께 기록합니다.
8. **주문·체결 → 주문 선택 → 주문 조사 내역·마지막 대조**: 주문의 현재 조사 사유, 해당 주문의 체결 이벤트, 전체 계좌 대조 시각을 구분하고, 정확한 주문 번호에 연결된 과거 감사 기록을 50건씩 더 읽을 수 있습니다. 전체 계좌 대조 성공을 그 주문의 접수/취소 확정으로 바꾸지 않습니다.
9. **실행 기록 → 기록 선택 → 내 실행 기록 메모**: 500자 메모를 별도 로컬 SQLite에 저장합니다. 앱 재시작 후 다시 읽을 수 있고 최근 10개 수정 이력을 확인합니다. 다른 창의 새 버전을 덮어쓰지 않으며, 충돌하면 저장 메모 다시 읽기를 사용합니다. 실행·감사 원본은 수정하지 않습니다.

로컬 저장 위치: 실행파일에서는 `%LOCALAPPDATA%/live_trader/logs/operator-review.sqlite3`이며, `LIVE_TRADER_DATA_DIR`를 지정했다면 그 경로 아래 logs를 사용합니다. 비밀키나 주문 권한을 저장하는 파일이 아닙니다.

검사: `npm run test:operator-insights`, `.venv/Scripts/python.exe -m unittest discover -s tests -p test_operator_review.py`, `npm run ui:operator-insights`. 브라우저 검사는 합성 API 응답과 임시 로컬 정적 서버만 사용합니다. 실제 주문·브로커 조회·텔레그램 전송 없이 검증합니다. Windows 패키징은 `powershell -ExecutionPolicy Bypass -File build_exe.ps1 -SkipDependencyInstall -PendingOnly`로 기존 고정 EXE를 보존한 채 준비합니다.
